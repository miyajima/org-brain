# スコープ: OrgBrain 全体機能・UX評価と96点到達

> ユーザー承認済み計画を与件として固定する。

---

## ゴール（何を決める / 何を伝える）

現行OrgBrainのLocal、Cloudflare、AI提案、Console個人／チーム利用を同じ評価方法で採点し、重点4軸各96点以上・その他各90点以上・総合96点以上へ改善する。未検証領域を平均点で補わず、証拠coverageと外部変更境界を明記する。

## 論点（イシュー）

| # | 論点 | 種別 | 状態 |
|---|------|------|------|
| I-01 | 現行実装の主要フローは説明なしで完遂できるか | 調査で分かる | 調査中 |
| I-02 | 採点値は再現可能な証拠と測定値から計算できるか | 調査で分かる | 調査中 |
| I-03 | 96点を阻害する最高影響の摩擦はどこか | 調査で分かる | 未解決 |
| I-04 | Cloudflare liveの対象と安全な実行境界は何か | 判断が必要 | 承認待ち |

## 背景

### なぜやるのか

過去にConsole中心96.4点と、Local・Cloudflare・AI・管理画面を含む暫定88.6点がある。対象範囲と証拠coverageが異なるため、現行リリース判断へそのまま転用できない。評価方法を固定し、実操作と自動検証を結び付ける必要がある。

### 現状の痛み

- 過去評価ごとに軸や重みが異なる。
- 改善後scorecardに手入力の点数配列が残る。
- Cloudflare liveとVoiceOverの未検証が総合点から見えにくい。
- Consoleの見た目、CLI導入、AI安全性を一つの印象点に混ぜると原因が追えない。

### 前提

- 現行commitを基準にfreshな証拠を取得する。
- 製品の公開APIとDB schemaは評価基盤のためには変更しない。
- Cloudflare liveは明示承認後に限る。

## 決定事項

| 項目 | 内容 |
|------|------|
| 対象 | Local、Cloudflare、AI、Console個人／チーム、Decision中心導線 |
| 重点軸 | わかりやすさ、画面のシンプルさ、操作のしやすさ、目的到達 |
| 証拠 | current runのinteractive、automated、rendered、staticを区別 |
| 合格 | 重点各96、その他各90、総合96、coverage 95%、重大・高0件 |

## スコープ

### 含める

| 項目 | 備考 |
|------|------|
| 評価方法と機械可読rubric | 恒久文書、JSON、schema、validator |
| fresh監査 | in-app Browser、ローカルCLI、AI fixture、自動テスト |
| UX改善 | findingに直結する最小の実装とテスト |
| 最終レポート | 改善前後、coverage、証拠、残存リスク |
| Cloudflare preflight | dry-runと承認に必要な対象整理まで |

### 含めない

| 項目 | 理由 |
|------|------|
| 無承認のdeploy・OAuth・hook・データ作成 | 外部変更境界を越えるため |
| unrelated refactor | 評価改善との因果が弱く、回帰範囲を広げるため |
| WCAG準拠の断定 | 自動検査と画面証拠だけでは証明できないため |

## 制約

| 種類 | 内容 |
|------|------|
| 証拠 | 過去画像を現行点の根拠に使わない |
| Git | unrelatedな変更を保存・上書き・破棄しない |
| 実行 | Cloudflare live前に対象とrollbackを提示して承認を得る |
| スコア | 未検証をN/A再配分で隠さない |

## 成果物の受け手

| 受け手 | 期待する粒度 | 用途 |
|--------|-------------|------|
| 利用者 | 結論と主要画面 | 操作性の確認 |
| 開発者 | finding、再現手順、テスト | 改善実装と回帰防止 |
| リリース判断者 | score、coverage、未検証境界 | 出荷判断 |

## 成功基準（Done の定義）

評価方法と再計算可能なscorecardが残り、ローカルで確認できる主要フローの改善・再評価が完了している。Cloudflare live未実施の場合は、現行点を暫定とし、承認に必要な対象と未達条件を明示する。
