# 既存成果を提示して着手前に作業範囲を決める

調査・分析・文書作成の登録済み対象へ、既存成果を提示して作業範囲を選ぶローカルClaude CLIの確認フローを実装した。2026-10-30には、モデル起動前の確認と差分だけの生成・ホスト結合へ改善し、各条件10回の主比較で記憶なし比トークン36.5%・機械時間38.1%減を確認した。最終補強版の単独3条件確認でも削減を確認。主比較と補強後の確認、並行負荷があった確認を分けて記録した。追加合計36開始・累計419開始、API換算0.6425994 USD。実利用者の判断時間・自然利用は未観測で、クラウド展開なし。

## 確認の流れ

今回の依頼を既存成果で満たせそうな候補が見つかった場合に、着手前に一度確認する。単に関連する記憶や手順があるだけの場合は、作業完了の候補にはしない。

1. 閲覧権限のある成果から、目的・対象・期間・版が今回の依頼に近いものを探す。
2. 元の担当者、実行日、対象・条件、成果物への参照、短い結論、今回を満たす範囲と不足・変更・未確認事項を示す。不明な情報は不明とする。
3. ユーザーに「既存成果で完了」「差分だけ実施」「全体を実施」を提示する。差分が不明なら、その範囲を確認する。
4. 実際の回答を待つ。未回答や初期選択を継続・完了の承認にしない。既存成果で十分という回答後は、その範囲で新たな調査・生成・実行に着手しない。
5. 明示された差分がある場合は、その部分だけを作業範囲にする。全体実施が選ばれた場合はその指示を守り、同じ確認を繰り返さない。

確認待ちの間は成果の所在や適用条件の確認までにとどめ、対象の調査・生成・実行を先行しない。アクセス権がない成果の内容や存在を他の利用者へ示さない。過去の成功報告だけで現在の状態まで完了扱いにしない。

## 作業全体を省ける候補

|優先|依頼の種類|提示する既存成果|既存成果で完了できる条件|継続する場合の差分|
|---|---|---|---|---|
|1|調査・選定・比較|既存の調査報告、比較表、出典|今回知りたい点・対象・時点を満たす|新しい候補、評価軸、最新情報だけ|
|2|集計・分析|既存の集計表、レポート、入力データ版|対象期間・母集団・指標・データ版が十分|新しい期間、指標、データだけ|
|3|資料・文書の作成|完成済みの手順書、提案書、FAQ|目的・読者・必要な内容を満たす|読者や用途に合わせた変更だけ|
|4|設計・方針の検討|既存の設計、採否、比較と理由|判断に関わる要求・制約が維持されている|変わった要求に関する再検討だけ|
|5|不具合の原因調査|既知事象、原因、復旧手順と検証記録|症状・対象版・環境が対応し、ユーザーの目的が既存説明で満たせる|異なる症状や未解決部分だけ。修正・復旧そのものは別に判断|
|6|レビュー・検証|対象版と範囲が明確なレビュー・試験結果|対象内容・環境・検証範囲が一致し、今回必要な確認を満たす|変更箇所と影響範囲だけ|
|7|設定・導入・アクセス準備|現在の設定・利用可能性の確認結果|今回求める状態がすでに成立している|不足する設定・権限だけ|
|8|ジョブ・取り込み・生成の実行|同じ入力・対象期間の完了記録と成果物|今回の目的がすでに達成されており、追加の実行を必要としない|未処理分や失敗分だけ|
|9|確認・問い合わせ|既存の回答・合意と適用条件|今回の質問が解消され、回答の適用範囲が対応する|回答されていない点だけ|

優先順位は実装候補としての提案。最初は調査・分析・文書作成が扱いやすい。既存成果で目的を満たすかをユーザーが判断でき、作業を省く範囲も説明しやすいため。操作を伴う依頼では、参考になる成果があることと、今回の実行目的が達成済みであることを分ける。

## 観測と評価

既存成果の提示、ユーザーの完了判断、差分実施、全体実施、未回答を別々に記録する。「既存成果で完了」は、元の成果ID・版とユーザーの回答へ結び付けた成果物の再利用として扱い、モデルの原本読取・操作適用の記録へ置き換えない。

確認フローの検索・提示・回答の費用も計上する。省略できた作業件数と、後から不足が判明して再開した件数を測る。実行しなかった作業のトークンや時間は観測できないため、その費用を0や確定した削減量として扱わない。削減量の評価には、同じ成功条件での比較か、根拠と仮定を明示した推定が必要。

現行の比較と適用条件は [MEMORY_REUSE_LOOP.md](MEMORY_REUSE_LOOP.md)、測定済みの範囲は [直近の報告](../artifacts/memory-reuse-resolution-20261027/REPORT.md) を参照。

## CLIへの設定と適用範囲

`.local/memory-reuse/config.json`の`task_confirmation_mode`を`ask`にし、`task_workflows`へ対象を登録する。各対象は`kind`（research / analysis / document）、対象名、明示的な作業表現、最大4個の作業単位、原本ID・版、出典ファイル、環境・依存ファイル、期限、共有先、固定Nodeアダプターを定義する。アダプターの`task_workflow`を同じIDへ結び付ける。未登録の通常作業に一律の確認は追加しない。

明示入力は`<reuse_task>{"workflow":"対象ID","units":["単位ID"]}</reuse_task>`で指定できる。登録した具体的な作業表現からの一致も扱う。複数対象や不明な作業単位を勝手に選ばない。

UserPromptSubmitが既存成果の権限・出典・実装・環境・期限・ファイルハッシュを確認し、作成者・実行日・既存/今回の範囲・差分・成果物を含むAskUserQuestionを案内する。PreToolUseは回答前と既存成果による完了後の作業を拒否する。実際のPostToolUseの質問IDと回答を照合するまで、選択を有効にしない。差分が未指定なら作業単位を追加確認する。

差分・全体の選択後は、その対象の固定アダプターのみを使う。差分では承認範囲外の再調査や既存部分の書き換えを拒否する。全体実施では対象全体を現在の原本から読み、成果物を作る。CLIコマンドの直接呼び出しにも同じ制限を適用する。原本や成果が途中で変われば、確認済みの完了へ置き換えない。

`run`の実ネイティブ完了と成果物ハッシュが揃った文章成果を、元の原本ID・版を参照する`completed_work`の派生成果として登録する。共有には明示grantと元原本の読取権限が必要。成果自体を新しい原本知識として数えない。2026-10-30に通常作業用の対象登録と観測を追加した。プロジェクト内ファイルだけを原本にする対象では、実際のファイルのパスとハッシュを保持し、新しい記憶として登録しない。[通常作業の開始と測定](MEMORY_REUSE_ORDINARY_WORK.md)を参照。導入と自然利用の効果は別に確認する。

設定後のフック導入には既存の`install`を使う。登録対象がある場合だけ、既存フックを保持してPreToolUseを追加する。戻す場合は`task_confirmation_mode=off`とし、次のユーザープロンプトから従来の実行を使う。

状態は`.local/memory-reuse/task-confirmations/`、実操作と質問は既存の`native-evidence/`、最終結果は`last-observation.json`の`task_completion`に記録する。原本のモデル利用や操作単位の結果適用へは置き換えない。評価用の回答は`decision_source=simulated`とし、通常のネイティブ利用者の回答と分ける。

[比較条件](../artifacts/memory-task-confirmation-20261029/PROTOCOL.md)と[実測報告](../artifacts/memory-task-confirmation-20261029/REPORT.md)を参照。過去成果作成3回、比較18回、初回診断2回をすべて計上した。初回は質問ツールが公開されず未回答で停止したため、両条件で`--permission-prompt-tool stdio`を指定して比較し直した。非対話`-p`では質問の受け口が必要で、回答を得られない場合は作業を進めない。

境界テスト17件、既存回帰44件、使用量集計2件、独立監査の判定3件を通過。合成資料・模擬利用者による各選択3件の小規模な比較であり、実利用者の採用率・判断時間・再開率は未観測。各フックの個別CPU費用、親の実装/監査費用、実請求額は未取得。

実装はClaude Codeの[PreToolUseによる質問入力の取り扱い](https://code.claude.com/docs/en/hooks#tools-that-require-user-interaction)を参照した。費用は[公式の使用量・費用の説明](https://code.claude.com/docs/en/agent-sdk/cost-tracking)に従い、モデル別の全呼び出し量を使い、欠測を0で補完しない。クライアントのAPI換算額は実請求額と区別する。確認日: 2026-10-29。

## モデル起動前の確認と差分だけの生成（2026-10-30）

確認をモデルへ一往復させる前に、プロジェクト内のターミナルで受け取る起動コマンドを追加した。利用者の選択、原本や既存成果の版・条件、今回の依頼文と対象、利用者とセッションを一回限りの記録に結び付ける。未回答では新しい作業をしない。別セッション・別利用者への流用、原本・成果・権限の変更を検知する。

差分だけ実施では、ホストが承認された新しい単位だけを固定アダプターで実際に読み、その結果をモデルへ渡す。モデルは新しい単位だけを`patch`として生成する。ホストが対象外の既存部分をそのまま結合し、成果物全体を検証する。既存部分をモデルへ再送・再生成させない。ホストの読取と注入は`host_context`として記録し、モデルが原本を読んだという記録へ変えない。新しい差分の実操作は従来どおり実際のBash呼出・PostToolUse・成果物ハッシュを照合する。

使う場合は、既存の対象登録とフック導入に加えて`task_local_mode=on`を設定し、対象の`local_source_field`へアダプターの読取結果のフィールド名（例:`source_sections`）を指定する。このフィールドは承認された単位だけの完全な現在資料を返す契約とする。以下の合成資料による主比較時点では通常設定を変更していなかった。その後の通常作業への接続は[通常作業の開始と測定](MEMORY_REUSE_ORDINARY_WORK.md)を参照。

依頼をJSONファイルに保存する。例は`{"prompt":"<reuse_task>{\"workflow\":\"対象ID\",\"units\":[\"a\",\"b\",\"c\"]}</reuse_task>"}`。プロジェクトのターミナルから`node scripts/memory-reuse-task-local.mjs --request task-request.json`で起動する。セッションIDは自動生成する。起動前に既存成果と3択を表示し、明示的な回答を受け取ってから新しいClaudeプロセスを起動する。既存成果で完了を選んだ場合はモデルを起動せず成果の所在を返す。直接Claudeを起動した場合は従来のAskUserQuestion経路を使う。

非対話の模擬回答は、テスト設定と専用の評価用環境変数がそろう場合に限る。通常利用は実ターミナルで回答する。`--prepare-only`はモデルを起動せず準備までで終了する。実際の利用者の回答を評価用の固定値へ置き換えない。

新経路9件を含む確認テスト26件と既存回帰44件、独立集計のテスト2件、lint、およびモデル起動なしの準備を通過した。その後、記憶なし／現行／改善版各10回を実モデルで比較し、改善版は記憶なし比で総トークン36.5%・機械処理時間38.1%減となった。検索・ローカル確認・資料準備・注入・追跡・結合を含む。30/30で必須事項と再利用証拠の照合に合格し、個人・チーム模擬の両方で削減した。[比較条件](../artifacts/memory-task-delta-20261030/PROTOCOL.md)と[実測報告](../artifacts/memory-task-delta-20261030/REPORT.md)を参照。主比較30回はv2の値。最終補強版v3は、注入前の全モデル操作と期限切れ確認のホスト読取を拒否する。補強確認3回は回帰テスト並行で時間が乱れたため生値を残し、追加承認後の単独3回で記憶なし15.74秒に対し改善版9.14秒を確認した。主比較へ合算しない。追加合計36回・累計419回、API換算0.6425994 USD、動作・再利用証拠の照合は36/36合格。短い合成資料と模擬選択の結果で、実業務用の対象登録・実利用者の判断時間・自然利用は未観測。実請求額と親実装・監査費は未取得。クラウド展開なし。
