# OrgBrainの実モデル使用量・完了時間の比較

## 結果

**関連する記憶が見つかる条件では、追加記憶なしより総トークンが24.5%、
キャッシュなし入力が15.3%減った。平均完了時間は9.2%短くなったが、
自動保存の調査は2回とも遅くなった。短縮形式が旧形式より優れているとは確認できない。**

| 条件 | 受入成功 | 平均完了時間 | 総トークン・6回合計 | キャッシュなし入力・6回合計 |
|---|---:|---:|---:|---:|
| 追加記憶なし | 6/6 | 176.0秒 | 1,754,562 | 370,535 |
| 改善後の短縮形式 | 6/6 | 159.8秒 | 1,324,689 | 313,688 |
| 旧形式 | 4/6 | 算出不可 | 2回分不明 | 2回分不明 |

旧形式は利用履歴の1巡目と自動保存の2巡目で240秒以内に最終回答を出せず、
その2回は利用量の最終イベントも得られなかった。成功した4組だけを参考比較すると、
短縮形式の総トークンは**6.4%増**、キャッシュなし入力は**30.7%増**、
時間はほぼ同じ（0.02%短縮）。未完了の2回を除いた値なので、旧形式を含む条件全体の
削減率には使えない。2回の時間切れだけから信頼性の一般的な優位も断定しない。

追加記憶なしと改善後を同じ課題の2回平均で比べると、次の結果になった。

| 課題 | 記憶なし | 改善後 | 時間の変化 | 総トークンの変化 |
|---|---:|---:|---:|---:|
| worktreeの設定解決 | 142.9秒 | 108.9秒 | 23.8%減 | 15.8%減 |
| 検証済み利用履歴 | 230.1秒 | 197.3秒 | 14.2%減 | 32.2%減 |
| eager自動保存 | 154.9秒 | 173.2秒 | 11.8%増 | 15.9%減 |

総トークンとキャッシュなし入力は6組すべてで減少した。時間が短縮したのは6組中4組。
独立した課題は3件だけで、同じ課題の反復は独立サンプルとして扱っていない。
課題単位で再標本化した時間削減率の記述的95%区間は **-11.8%〜23.8%** で、
一般的な速度改善はまだ確定できない。

今回の結果は、記憶の返却サイズだけでタスク全体の効果を判定できないことを示す。
再調査の回数、推論・回答生成、キャッシュの違いを含む使用量を評価する必要がある。
自然な検索でのヒット率、自動抽出、デスクトップの通常セッション、コード修正作業、
実請求額の削減はこの比較からは検証できていない。

実験で完了した16回の既知使用量は計 **3,834,752トークン**。時間切れ2回の使用量は
不明であり、この値は実験全体の下限となる。準備・集計を行った親タスクの使用量は含まない。

再計算できる[集計JSON](../artifacts/memory-efficiency/2026-09-23/live-codex/report.json)と
[整合性検証](../artifacts/memory-efficiency/2026-09-23/live-codex/validation.json)を保存した。
完了した16回答は引用照合・内容基準を満たし、全18回でソースの同一性を確認した。

## 比較条件

Codex Proの `gpt-6-astra` / `max` を使い、同じソース・質問・受入基準で
次の3条件を比較する。

- `none`: OrgBrainの追加記憶なし。
- `full`: 改善前の実装・既定値で検索した記憶を渡す。
- `compact`: 改善後の実装・既定値で検索した記憶を渡す。

対象はworkspace設定解決、検証済み利用履歴、eager自動保存の3つの保守調査。
各条件を2回実行し、合計18回を逐次実行する。順番は6通りを使って均等化する。
評価用のソースコピーは固定し、読み取り専用で調査する。

ソースで裏付けた各2件の記憶を隔離した評価用DBに用意する。初期の長い検索語は
3件ともヒットしなかったため、モデル実行前の準備段階で短い主題の検索語に変更した。
これは**関連する記憶が見つかる条件での再利用効果**の比較であり、自然な問い合わせの
検索再現率、自動抽出の成功率、現在の本番記憶による効果を測るものではない。
通常の記憶DBは使わず、測定セッションから自動記憶を作らない。

## 計測と受入

Codex CLIの `turn.completed.usage` を保存する。キャッシュ済み入力は入力の内数、
推論出力は出力の内数として扱い、二重計上しない。欠損値はゼロとみなさない。

完了時間はCodex CLIの起動から終了までと、記憶検索プロセスの時間を含む。
既存記憶の再利用を比べるため、評価用DBへの記憶投入時間は除外する。
投入時間を含めた値も別途保存する。失敗・制限時間超過は残し、再試行はしない。
最初の制限時間超過で一度停止した後、既存試行を再実行せず未実行の条件だけを継続する
変更を `continuation.json` に記録した。上限はすべて240秒で統一している。
時間切れを「240秒で完了」と扱わず、完了時間と使用量は欠損として残す。
欠損を含む条件の成功ペアだけの差は、条件全体の削減を証明しない。

回答の引用が固定ソースに存在することを自動照合し、親エージェントが4項目ずつの
内容基準を確認する。これは独立した第三者評価ではない。利用履歴の基準には、
実行結果の確認前に発見した誤記の訂正が1件あり、`protocol-errata.json` に残している。
行動利用の記録には行動証拠が必要で、結果・効果の確定には追加の結果証拠が必要となる。

料金はAPI単価で換算しない。Codex Proのタスク別請求額はこのログにないため、
**実請求額の削減は、この比較からは判定できない**。トークン削減をそのまま
利用枠や月額料金の削減率とは呼ばない。

Gitには集計・検証記録を保存し、環境依存の絶対パスはプレースホルダーに置き換えた。
生ログ・評価用DB・固定ソースは、ハッシュを確認してローカルに保管している。
保存先と再監査の条件は[成果物の説明](../artifacts/memory-efficiency/2026-09-23/README.md)を参照。

モデル実行時はユーザー設定・プラグイン・自動フックを読み込まない隔離CLIを使う。
モデルと推論強度は普段の設定に合わせるが、デスクトップの通常セッションと同一の
実行環境ではない。コピーはCLI・共有モジュール・scripts・docs・migrationsの範囲で、
appsは含まない。モデルが対象外のappsを探した失敗も試行ログに残す。
プロバイダーのキャッシュは消去できず、同じ課題の反復もあるため、
3課題の少数サンプルから普段の全タスクに一般化しない。

```sh
python3 scripts/memory-efficiency-live.py prepare \
  --output NEW_OUTPUT_DIRECTORY --baseline-root BASELINE_CHECKOUT
python3 scripts/memory-efficiency-live.py run --output NEW_OUTPUT_DIRECTORY
python3 scripts/memory-efficiency-live-report.py NEW_OUTPUT_DIRECTORY
```

`run` は実際にCodexの使用量を消費する。完了済みの出力ディレクトリは再利用しない。
