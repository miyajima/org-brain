# 通常のClaude CLIで既存成果を再利用する

このプロジェクトの調査・分析・文書作成を、モデル起動前の確認から始める。対象はローカルだけとし、共有ハーネスやクラウドは変更しない。

## 作業開始

導入は `node scripts/memory-task-project-install.mjs` で確認し、`--execute` で反映する。設定は `.local/memory-reuse/config.json`、プロジェクトのフックは `.claude/settings.local.json`。既存の記憶フラグ、結び付け、操作アダプター、フック、許可を保持し、導入前の両設定を `install-backups/` に保存する。

通常作業はプロジェクトのターミナルから開始する。

```sh
pnpm claude:work list
pnpm claude:work research
pnpm claude:work analysis
pnpm claude:work document
```

実際の依頼は `--prompt '依頼文'`、対象は `--units 単位1,単位2` で絞る。利用できる単位は `list` に表示する。初回に限定した成果を作り、後日対象を追加すれば、既存部分を保持して差分だけ作業できる。

調査は現行の再利用実装と制限、分析は保存済み比較結果の再集計、文書作成はこの操作手順を対象に登録する。別の案件・原資料は対象登録を追加してから使う。通常の `claude` へ全作業共通の確認を挿入するものではない。直接起動時でも登録済み対象の明示的な表現や `<reuse_task>` があれば従来のネイティブ確認へ接続する。

## 作業範囲の選択

条件の合う既存成果があれば、作成者・実行日・成果物・既存の範囲・今回の範囲・不足分・短い要旨を表示する。実際に内容を読み、番号で選ぶ。未回答や空欄では作業しない。

- 既存成果で完了：十分な成果へのリンクを返して終了する。Claudeモデルを起動しない。
- 差分だけ実施：不足する単位だけを実際の資料から読み、モデルはその単位だけを生成する。既存部分はホストが変更せず結合する。不足分が未指定なら対象を追加選択する。
- 全体を実施：依頼した単位を現在の資料から作り直す。

資料のバイト列、対象・単位、Nodeと実装の版、利用者、成果物のハッシュ、有効期限が一致する場合だけ提示する。現在の登録期限は7日。変更や権限不一致、確認後30分の経過を検知したら作業を止める。

この対象の原本はプロジェクト内ファイルであり、新たな「検証済み記憶」を作成しない。実際に完了したネイティブ操作から、ファイルのパスとSHA-256を参照する `completed_work` を登録する。ファイルによる成果の共有先は登録しない。別の利用者へ共有するには、その利用者の出典読取権限を確認できる経路が必要。

資料本文は、セッション・対象・読取結果のダイジェストと結び付けた起動時の追加文脈で渡す。フックには短い範囲とコマンドを残す。Claudeのフック追加文脈は10,000文字を超えると全文がファイルへ退避され、モデルには短いプレビューが渡るため、長い原文の注入に使わない。起動時の文脈がないまま長い原文を渡そうとした場合は拒否する。資料を切り捨てて完了扱いにはしない。[Claude Codeの公式フック仕様](https://code.claude.com/docs/en/hooks#add-context-for-claude)（2026-10-30確認）。

## 記録と効果の確認

```sh
pnpm claude:work status
```

作業ごとの記録は `.local/memory-reuse/work-observations/<session_id>.jsonl` に残す。確認して中止した場合、既存成果で完了した場合、モデルを起動した場合を分ける。画面表示から実回答までを確認の経過時間として測り、読んでいた時間や実際の人件費とは区別する。能動的な確認時間は本人の申告がなければ欠測。確認を省いた作業や模擬回答を、実利用者の確認時間へ変えない。

ClaudeのStopで、実操作と成果物の検証結果、現在のセッションの入力・キャッシュ作成・キャッシュ読込・出力トークンを集計する。重複するメッセージIDを二重計上しない。4区分の欠測・不明なモデル・壊れた記録は不明のまま残す。API換算費用と実請求額を区別し、対話全体の経過時間には人の入力待ちも含まれると明示する。

効果の比較では、同じ資料・対象・成功条件について `--control` の記憶なしと再利用を比較する。両方でホストが対象資料を準備するため、元資料の再利用だけの効果を比較できる。API使用量の大小だけで採用とせず、正確さ・制約・誤適用・手戻りも確認する。利用者の確認と成果確認を含む総時間が記憶なしを下回った場合だけ、人を含む時間削減を主張する。

評価のために依頼した作業は `--origin solicited`、自発的な通常利用は既定の `organic` として別に集計する。`--prepare-only` はモデルを起動しない。通常設定では模擬回答を許可しない。追加評価を行う前に、CLI実行回数とAPI換算上限を承認する。

無効化は `task_local_mode=off` と `task_confirmation_mode=off`。通常の `claude` は継続できる。設定全体を戻す場合は導入時のバックアップと導入後の無関係な変更を照合し、必要な箇所だけを戻す。

## 全体実施の負担を抑える設定

2026-10-31のローカル検証後、このプロジェクトでは次を有効にした。

```json
{
  "task_request_mode": "sections_stdin",
  "task_compact_receipts": "on",
  "task_full_checks": "current_sources_only"
}
```

記憶参照IDを持たないファイル原本の作業では、ホストがタスク・操作・単位を確定し、モデルは節の本文だけを引用符付きheredocの標準入力へ渡す。本文に引用符やコマンド例があっても、シェル引数の引用処理をモデルに任せずに済む。完了応答はパス・SHA-256・実呼出IDに短縮する。実アダプターの全文出力は非公開の検証記録へ残し、実際のネイティブ入力・出力・完成ファイルと照合する。

「全体を実施」の選択後は旧成果の再検査を省く。選択前の版・権限・有効期限・成果物の確認、現在の資料と実行範囲の検証は維持する。「差分だけ実施」と「既存成果で完了」は旧成果を使うため再検査する。原本の記憶参照IDがある経路の利用報告も維持する。

起動コマンドと3択は変わらない。実モデル比較では改善版6件が完了し、記憶なし比で総トークン1.3%減・機械処理時間7.1%減だったが、出力と応答時間のばらつきを含む小規模測定である。全体実施で再利用した節は0件。人の判断時間は未測定で、人を含む削減効果は未確認。[測定と採否](../artifacts/memory-task-full-20261031/REPORT.md)を参照する。

3機能だけを戻す場合は、設定の `task_request_mode` を `json_cli`、`task_compact_receipts` を `off`、`task_full_checks` を `legacy` にする。設定全体を復元する場合はバックアップ以降の変更を保持する。評価用DBは通常DBへ取り込まない。
