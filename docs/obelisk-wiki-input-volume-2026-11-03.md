# 抜粋文字数とLLM入力トークンの違い（2026-11-03）

これまでの「抜粋量」は、モデルへ渡した資料本文の文字数を指す。
LLMへの入力トークン総数ではなく、本文だけのトークン数も別計数していない。
文字とトークンは異なる単位なので、文字数比をそのままトークン比にしない。

| 新規3問の合計 | 短縮後OrgBrain | Obelisk | 比率 |
| --- | ---: | ---: | ---: |
| 抜粋本文の文字数 | 12,094 | 4,941 | 約2.45倍 |
| CLI報告の入力トークン総数 | 54,138 | 49,995 | 約1.08倍、8.3%増 |
| 上記総数に含まれるキャッシュ読込分 | 12,160 | 36,480 | 条件ごとに異なる |

入力総数には、資料本文のほかに質問、回答への共通指示、JSONの項目、
Codex側の共通文脈なども含まれる。キャッシュ読込は入力総数の内数で、加算しない。
総数の比率は料金の比率ではない。以前の約20倍も、本文文字数の比率だった。
新しいモデル呼び出しや料金照会は行っていない。

## 文字数が多くなった場所

| 質問 | 短縮後OrgBrainの本文文字数 | Obeliskの本文文字数 |
| --- | ---: | ---: |
| 定期処理の時刻・対象・実績 | 490 | 534 |
| 3経路の反映範囲 | 421 | 474 |
| 異なる時点の差分作業比較 | 11,183 | 3,933 |

差は3問目に集中する。評価の検索に渡したのは「差分」「記憶なし」「確認」の3語で、
質問が指定する日時・実験まで絞る条件は渡していなかった。
全語一致する原本を優先する現実装でも、これらの語を含む資料は複数あり、
保存報告2件と通常原本6件、計8件が返された。
通常原本には約3,278文字の設定手順や約2,043文字の別の実験報告も含まれた。
この内訳は伏字処理前、モデル用の表は伏字・過去引用整理後である。

現実装は同じ原本IDの重複を除くが、質問に必要な実験の条件がそろったかは判定しない。
1件最大4,000文字・合計最大12,000文字・最大8件の枠内で複数文書を返すため、
必要箇所に絞る処理がまだ粗い。全語一致は必要性・実験の一致・回答の完全性を意味しない。

一方、今回固定したObelisk側の検索手順は、セッションの発言を単位に検索し、
各発言の先頭最大1,800文字と前後の発言を渡した。文書単位より短いが、
3問目では必要な古い各10回の報告を取得できず、その部分を不明と答えた。
少ない文字数だけを優秀さの証拠にはしない。製品全般の差ではなく、固定した今回の検索手順の比較である。

次の改善候補は、日時・実験IDで対象を分け、まず根拠になる行と前後だけを返し、
不足時に追加取得すること。今回この追加実装は行っていない。

`packages/orgbrain-cli/src/lib/wiki-recall.mjs`、
`artifacts/obelisk-wiki-holdout-20261102/obelisk-query.mjs`。
