# Markdown書式の整理と取得処理の改善（2026-11-14）

保存するメモリはAMP 0.4のMarkdownへ統一した。本文のほか、先頭のYAMLに条件・例外・出典を字下げで記載する。JSONのオブジェクト・配列を文書内へ埋め込まず、同じ出典を別のhash表へ繰り返さない。通信のJSON、JSON Schema、機械処理する評価結果は文書の保存形式とは別である。

## 実装したこと

- 索引の手順名・説明から、本文にその語がなくても対応する手順を候補にできる。
- 長い候補が全文で入らなくても、後続の短い候補が収まれば全文を返す。条件や例外だけを切らない。
- 自然文を分けて検索するとき、各部分で最終件数まで候補を絞り込まず、質問全体で順位を決める。所有範囲の指定は維持する。
- 旧0.3は従来の読み方を維持し、`#`やコロンを含む条件文を変えずに0.4へ保存できる。旧0.1・0.2の読込互換も残す。
- 新規作成用の索引・メモリのテンプレートを0.4へ更新した。個人WikiのOrgBrain用4手順も、内容・条件・例外・出典が同一であることを照合してから更新した。

## 同条件の回帰確認

同じ固定原本13件・AMPメモリ5件・自然文16問を使い、変更前後をそれぞれ2つの返却上限で確認した。計64回。新形式への変換では文書版以外の解析済み項目が同一であることを確認した。検索応答に必要な記述が含まれるかの試験であり、AIが生成した回答の採点ではない。

| 指標 | 上限1,200・変更前 | 上限1,200・変更後 | 上限4,000・変更前 | 上限4,000・変更後 |
|---|---:|---:|---:|---:|
| 必要情報が揃った質問 | 8/16 | 8/16 | 14/16 | 15/16 |
| 条件・例外等の不足 | 12/27 | 12/27 | 2/27 | 1/27 |
| 平均返却トークン | 1,067.25 | 1,074.63 | 3,766.44 | 3,793.75 |
| 検索エラー | 0 | 0 | 0 | 0 |

残る4,000トークンの不足はq07の再確認条件。1,200では改善を確認できていない。返却量は増えており、省トークン化や費用削減を達成したとはいえない。既知の問題で調整した回帰試験であり、未知の質問の精度や一般的な正答率ではない。

[全結果と実装hash](evaluation-markdown-20261114-results.json)を保存した。前の「JSONとMarkdownの保存形式だけ」の比較とは異なり、今回は取得処理も変更している。改善をMarkdown化だけの効果としない。

## 動作確認と適用範囲

関連125テスト成功。書式の変換、手順名からの取得、長い先頭候補と短い後続候補、検索部分ごとの早すぎる絞り込み、旧形式の条件保持は、修正前の失敗と修正後の成功を確認した。親の差分レビューと独立レビューを行い、独立レビューの旧形式に関する1件の指摘を修正・再確認した。

配布用CLIをビルドし、隔離した一時MCPへの実接続で新書式のツール説明、索引→ローカル起動の本文取得、出典2件の版・hash・範囲照合を確認した。個人Wikiのプロジェクト索引から4手順の検査も成功した。テンプレート2件は現行パーサーで読めることを確認した。

常駐MCPの実行ファイル・設定、Cloud版は更新していない。保存済み手順の内容にあるサーバー起動・本番公開は実行していない。根拠のhash照合は意味の正しさや過去の実行を証明しない。
