# Console operator UX

この文書は、組織の運用担当者向けに整理した主要画面と、現在の実装範囲を記録する。製品上の要件は [PRODUCT.md](../PRODUCT.md)、視覚仕様は [DESIGN.md](../DESIGN.md) を参照する。

## 目的と利用場面

担当者が「どんな知識が残っているか」「何を根拠としているか」「仕事でどこまで使われたと確認できるか」を理解し、必要な箇所を整える。自動蓄積を基本とし、人による確認・修正を組み合わせる。PCを主な運用環境、モバイルを主に確認する環境とする。

## 主要画面

| 画面 | URL | 担当者が行うこと |
| --- | --- | --- |
| ホーム | `/` | 蓄積と利用の概況、確認事項、最近の動き、プロジェクト別の利用、観測値と目標・改善を見る |
| 知識 | `/knowledge` | 記憶・判断・資料を検索し、選択した対象の内容・根拠・活用履歴・共有を確認する |
| 管理 | `/settings` | 組織・権限、AI接続と配布、運用と拡張を管理する |

主ナビゲーションはこの3画面とする。Decision、Map、Skill、Agent、Reviewは残る機能であり、主ナビゲーションを5項目に固定する旧要件は適用しない。

## ホーム

`HomeWorkspace.astro` は保存された記憶の件数、検索で取得された回数、採用が報告された回数を表示する。保存件数は全期間、利用集計は直近7日または30日として区別する。注意が必要な記憶・判断・処理から対象へ進み、最近の記録やプロジェクト別の利用も確認できる。

取得できない件数や利用指標をゼロに置き換えない。確認事項の取得が一部失敗した場合は、その制約を表示する。項目がない場合と、取得に失敗した場合で表示を分ける。利用報告は業務成果の確認と同一ではない。

`GoalWorkspace.astro` はプロジェクトの業務指標、現在値・目標・前回値・観測日時と改善を表示し、再測定の状況を確認する。業務指標は最新の観測値であり、ホームの7日・30日の利用集計とは区別する。機能と管理権限が許す場合に、観測値のsnapshot記録や、ソースに束縛されたimportを実行できる。取得処理の受付を、値の取得完了や目標達成と同一に扱わない。

## 知識の確認と修正

1. 種類と検索語で記憶・判断・資料を探す。
2. PCでは一覧を残したまま同じページの詳細を開く。モバイルでは詳細へ切り替え、一覧へ戻れるようにする。
3. 「内容」「根拠」「活用履歴」「共有」を切り替えて対象を確認する。
4. 対象の種類と権限が許す場合に、判断の修正・確認、記憶の利用停止、共有範囲の変更へ進む。

一覧の種類、検索語、選択対象、詳細タブ、利用履歴のcursorなどはURLに持たせる。資料の検索には検索語を用いる。記憶の一覧と利用履歴にはページ送りがあるが、全種類に共通した無制限の一覧取得があるとは扱わない。

記憶の活用履歴では「検索で取得」「採用」「実行」「結果確認」を別々に表示する。明示的に記録された段階だけを確認済みとし、後段の記録から前段の成功を推測しない。履歴がないことは未使用の証明ではない。判断・資料では閲覧可能な関連ノードを表示するため、記憶と同一の段階別履歴が揃うとは限らない。

共有範囲は取得したAccess Policyから表示する。取得失敗、閲覧できない対象、根拠なし、利用記録なしを同じ状態へまとめない。変更は既存APIへ送り、共有範囲や利用停止などの影響を確認してから適用する。

## 管理と専門機能

`settings.astro` は次のまとまりで、実効権限と機能の提供状態に応じて管理項目を表示する。

- 組織と権限: 組織、ユーザー、グループ、業務分類、プロフィール。
- AI接続と配布: 端末登録・無効化、エージェント、スキル。
- 運用と拡張: 処理状況、業務パック、業務指標、振り返り、改善アクション。

業務パック、業務指標、振り返り、改善アクションは、それぞれ `PackWorkspace`、`MetricWorkspace`、`RetrospectiveWorkspace`、`ImprovementWorkspace` として新しい管理画面内に統合されている。これらの操作を、補助URLへのリンクだけで提供する構成とは扱わない。

旧専用導入画面、graph、labなどの補助URLは残る。BaseLayout経由のOperatorLayoutと共通スタイルを適用する画面もあるが、すべての内部画面の構成を作り直したものではない。旧画面は機能仕様の参照元であり、旧視覚体系を維持する基準ではない。

エージェントではLoadoutの編集と、利用記録を付けないコンテキストのプレビューを扱う。スキル生成では対象Decisionの版を指定し、明示的な操作でprivate draftを作る。処理の詳細は管理画面内で確認する。グループのメンバー解除では影響を取得し、その確認対象のdigestを付けて明示確認後に変更する。組織のowner対応付けも管理項目に残す。これらは実装範囲の記録であり、操作完遂の認定ではない。

エージェントとスキルの一覧はACLで絞り込んだ後にページ分割する。選択IDの詳細は現在の一覧ページと独立して取得するため、一覧外の対象でも権限が許せば直接確認できる。Loadoutの変更では、カタログ外の既存割当、固定版、有効期限を保持する。割当全体を確認できない場合は置換編集を停止する。`AccessSettings` はエージェント・Loadout・スキルの共有範囲を確認・変更する。

`POST /settings` を使う管理フォームでは、成功時に処理側がlocalsへ記録した遷移先をmiddlewareが読み、303でGETへ移る（Post/Redirect/Get）。失敗時は再表示して入力を保持する。処理の受付、保存の完了、外部処理の完了は区別する。

## 文脈と権限

画面間のリンクではtenant、project、言語を引き継ぐ。プロジェクトの切替時は前の対象選択や履歴cursorを残さず、選択中のプロジェクトに合わせて確認し直す。言語は日本語・英語・中国語を扱う。

表示する項目や操作の可否には実効権限とcapabilityを用いる。認証とACLの正本は既存サーバーであり、URLのtenant/project指定や項目の非表示を権限付与・権限制御の代替にしない。この再設計はサーバー側の認証・ACLを変更するものではない。

## 実装資料

- `apps/console/src/layouts/OperatorLayout.astro`: 共通シェル、表示範囲、言語、確認ダイアログ。
- `apps/console/src/components/operator/HomeWorkspace.astro`: ホームの集計、注意事項、最近の動き。
- `apps/console/src/components/operator/GoalWorkspace.astro`: 業務指標、目標、観測値、再測定と権限付きの記録・取得。
- `apps/console/src/pages/knowledge.astro`: 知識検索と同一ページの詳細。
- `apps/console/src/pages/settings.astro`: 管理項目と補助画面への入口。
- `apps/console/src/components/operator/AgentWorkspace.astro`、`SkillGeneration.astro`、`TaskWorkspace.astro`: 管理画面内の詳細操作。
- `apps/console/src/components/operator/PackWorkspace.astro`、`MetricWorkspace.astro`、`RetrospectiveWorkspace.astro`、`ImprovementWorkspace.astro`: 管理画面内に統合した運用と改善の操作。
- `apps/console/src/components/operator/AccessSettings.astro`: エージェント・Loadout・スキルの共有設定。
- `apps/console/src/middleware.ts`: 管理フォーム成功時の303 PRGと補助URLの導線処理。
- `apps/console/src/styles/operator.css`: 平坦な面、文字、操作状態、レスポンシブ、既存画面へのスタイル適用。

## 確認範囲

この文書は要件とソースから確認できる画面構成を示す。最終のローカル検証結果は別途記録する。デプロイ、利用者による操作試験、UX受け入れ、業務成果は、この記録では確認していない。

全役割・全言語での完遂、モバイルと読み上げの実操作、残る補助画面の構成は、該当する証拠が得られるまで未確認とする。既存の [UX評価方法](PRODUCT_UX_EVALUATION_METHOD.md) の重み、証拠上限、品質ゲートは維持する。追加実装前のチェック結果と最終検証を分け、未確定の最終テスト件数は記載しない。主要画面の置換だけで合格や96点到達を認定しない。
