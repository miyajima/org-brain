# 着手前に既存成果を提示する確認フロー

## 上限と対象

承認済み360開始は消化済み。2026-10-29の明示回答で追加最大24回・累計384回・API換算0.75 USD上限を承認済み。調査・分析・文書作成の各3選択、計9課題の対照/確認あり各1回（18開始）と、過去成果を実モデルで作成する3開始を予定する。準備・失敗の予備3を含め最大24開始、累計384まで。API換算見積0.60 USD、停止上限0.75 USD、CLI単位0.05 USD。失敗・準備も台帳へ開始前に確保し、自動再送しない。実請求額・親実装費・CPU金額は別勘定で未取得。クラウド展開なし。

## 固定条件

- モデルclaude-sonnet-5-5、effort medium。使用モデルと全4区分トークンを確認する。
- 同じ合成資料・成功条件・操作アダプターを使う。各ペアの順序を交互にする。比較開始前に入力・実装・過去成果のcutoffを固定する。
- 既存成果は3回の実モデル準備で作られ、実ネイティブ操作と成果物ハッシュ、ID・版、出典、期限、権限を照合する。他利用者に明示grantを付けて共有を模擬する。
- 対照は既存成果を提示せず、今回の必要範囲を実施する。確認ありでは既存成果の作成者・日付・範囲・差分・成果物を示し、ネイティブAskUserQuestionで3択を提示する。
- 選択は事前固定した模擬利用者がPreToolUseのupdatedInputを通じて回答する。これは利用者の模擬回答であり、固定モデル応答を再生しない。モデルが実際に質問を提示したか、選択に沿って処理したかを測る。実際の人による回答や自然な採用効果とは扱わない。
- 既存成果で完了では要求が過去成果の範囲で満たせる課題を使う。差分だけでは要求全体を過去部分＋追加部分で満たす。全体実施では要求全体を改めて実施する。同じ最終成果条件で比較し、要求を弱めて削減としない。
- 未回答・キャンセル・未知の回答・明示差分なし・権限違い・出典/成果物の変更・未完了の操作・架空IDはローカル境界テストで確認する。曖昧な回答を承認へ変換しない。

## 評価

成功、必須事項保持、誤った完了、範囲外操作、質問前の操作、欠測、成果物IDと元/今回のネイティブ操作IDの対応を照合する。提示・ユーザーによる既存成果の受入・モデルの原本利用・新規操作を分ける。

総トークンと準備＋CLI総時間には検索、提示、質問と回答、利用確認、ハッシュ照合を含める。模擬回答の待機時間と機械処理時間を分け、実際の人の判断時間は未観測とする。過去成果の作成3開始は別勘定で併記し、既存成果がある当回と作成費込みの回収を分ける。

評価の主目的は、作業全体の省略と差分への限定が正しく成立すること。全体実施の選択では確認の追加費用が増えても、そのまま報告する。全選択を混ぜた平均だけで採用効果を主張しない。合成評価と実業務・実メンバーの利用は分ける。

## 実CLI初回の修正

CLI 2.1.311ではPreToolUse回答フックのみではAskUserQuestionが公開されなかった。失敗1回と旧条件の対照1回を保持し、両条件へ `--permission-prompt-tool stdio` を追加して比較を最初から行う。合計23開始予定、残り予備1。未回答で新規操作ゼロを維持した。モデル応答・回答の捏造は行わない。
