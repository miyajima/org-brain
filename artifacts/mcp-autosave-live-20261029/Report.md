# MCP経由の分類別自動保存の確認

2026-10-29、設定済みローカルMCPと同じ本番SQLiteを使い、検証専用テナント
`autosave-validation` で保存後の読み戻しを確認した。通常テナントの記憶とは分離した。

- 提案は `fact / proposal / unconfirmed` として自動保存された。
- 実際のユーザー原文と照合した証拠がある判断は
  `decision / adopted-decision / explicit_user_choice` として自動保存された。
- 設定済み実行ファイルへの検証用MCP接続を閉じ、新しいプロセスで再接続した。
  同じ提案を別イベント・別出典で保存すると、既存IDの版が1から2になり、
  両方の出典と発生イベントが保持された。
- 条件が異なる提案は別IDとして保存された。
- 分類不明の1件だけが `quarantine` に残った。
- 保存された3記憶はすべて `unverified` で、検証済みには引き上げられていない。

結果は [receipt.json](receipt.json) に記録した。検証用クライアントの再接続を確認したもので、
このチャット自身の接続を切り替えた記録ではない。Codexの画面操作はツール側で制限された。

当時の自然なStopによるモデル抽出は月間予算で停止していた。
使用量498,512、上限500,000トークンに対し、次の呼び出しには2,800トークンの
予約枠が必要だった。予算は変更していない。この確認を、実モデルによる新たな
抽出や自然な会話全体の自動保存の成功には置き換えない。

設定と再利用条件は [分類別自動保存](../../docs/MEMORY_CLASSIFIED_AUTOSAVE.md) を参照。
