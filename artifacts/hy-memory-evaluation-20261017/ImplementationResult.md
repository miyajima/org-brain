# 記憶抽出の情報欠落改善: ローカル実装結果

2026-10-17。承認された改善プランのうち、P0の読取り・診断、P1の入力効率・依存関係・既存理由欄を実装した。製品ソースの変更であり、インストール済みランタイムの更新、本番有効化、外部モデルによる完全経路評価は行っていない。

## 実装したこと

- 同じturn_idの連続するcontextをまとめ、前半のuser/tool証拠を保持。別ターンをまたぐ同名IDは結合せず、同一ターン内のworkspace変更は停止する。8MiB制限は論理ターン全体に適用し、指定ターン以外の古い履歴は累積しない。
- system/developerロール、内部推論、子セッション、直接のエージェント調整呼出しと対応結果を除外。Stopではfinalを要求する。offlineでは完了マーカーも要求できる。opaque wrapperから子履歴を確実に識別する範囲は未解決として残す。
- 親本文の切捨て、snippet/event上限、入力予算、先頭spanの途中切捨て、読取りの除外を、原文を含まない件数・ID・理由で診断できるようにした。
- coverageは選んだツール結果のcall_idに対応するeventだけを送信。group IDの重複をpromptから除き、同じrequest形でhook/API/workerが予算判定する。元ID・offset・hash、全poolと検証用eventは保持する。
- 人が連続して明示した理由・例外を決定とまとめる。失敗→修正→成功は、同じ操作名・引数hashと実際の後続成功が対応する場合にまとめる。別操作の成功やAIの理由を人の理由として接続しない。理由・却下理由・決定の適用条件はverifierでも人の原文に照合する。
- coverage/A+のpromptに既存のrationale、why_it_worked、reuse_when、reason_rejected、avoidance_rule欄を戻した。理由が原本になければgapとする。
- prompt・出力schemaのfingerprintをAPIとworkerで照合。旧policyの未完了ジョブを新方式で送信せず、既存の予約・checkpointも変更しない。旧結果のhashを書き換えて再開する手順は設けていない。

## 検証と残る段階

失敗を先に確認してから、loader、予算・依存関係、旧policy送信防止を修正した。関連Vitest 120件＋Node 53件、shared/API/workerの型チェック、shared契約チェックが通過した。fixture providerで、条件付き2回目・checkpoint・会計・allowlist・重複送信防止も回帰確認した。

独立レビューで見つかった4件（APIの全event予算化、注入文、AI理由の誤帰属、直接MCPチャット読取り）を失敗テストで再現して修正した。さらに重複field名の検証・正規化差とMCPの追加形式・名前fallbackを失敗テストで再現し、重複名を正規化前に拒否、ツール名の共通読取りで除外するようにした。再レビューの最終判定は別途記録する。

人による正解ラベル、providerを使ったA/B/C完全経路、精度・保持・実費の固定評価は未完了。原本の理由なし/未検証を確定したとみなしたり、語句検出タグを人の正解へ変えたりしていない。75件調整＋未使用425件の条件も維持する。P2の検索・原文展開の再設計は今回の実装に含めていない。
