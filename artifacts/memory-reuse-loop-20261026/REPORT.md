## 実験の経路と改善

初回比較は案3→2→1→6→4→5の順に各20回。その後、案件メモを案件ごとの1枚へ修正し、手順と結果の実適用を明示的に追跡する形に改め、案1・4・5を事前固定の別入力Bで各1回再比較した。object-r1の2回は除外パイロットで本比較に混ぜていない。各実行の正確な順序・引数はattempts.jsonに保持。当時の個別ソースハッシュは後半から記録しており、先行比較の欠測を後付けで埋めていない。結果の最終比較では生成側・利用側のハッシュ記録が揃い、一致を確認した。採否は各案の最後の比較だけで判定し、旧試行の費用は捨てていない。

結果再利用は、入力・出典版/バイト・Nodeとアダプター/エンジン版が一致する以前の検証済み結果を参照する。最終比較8件すべてで、実際のClaudeが明示的なapply_artifactを選び、保存された計画を現行の7条件で再検証して適用した。実モデルの応答を固定文へ差し替える処理はないが、計画自体は結果キャッシュから取り出すため、モデルが毎回独立に計画を再生成した評価でも、検証CPUを省略できた証拠でもない。時間・トークン差はこの利用経路全体の差である。別の通常applyではモデル提案の全フィールドが保存結果と同一のとき検証結果を使える実装もあるが、これは動作テストでの確認であり、この8件の実測経路とは区別する。共有結果は明示許可と原本権限の両方を満たす必要がある。比較開始前のcutoffを固定し、記憶なし側がその比較中に生んだ結果を記憶あり側へ流していない。生成元・利用者・版照合はaudit.jsonに記載。

最終比較後、通常フックで観測された問題を修正した。限定的なBash許可に合うコマンド表記、会話ログファイルがない場合の実PostToolUse記録による照合、構造化本文の機微情報検査、UUIDと電話番号の誤判定、会話内で提示済みの版の抑制とPreCompact時の解除。通常フックの実モデル統合確認は4回中最後の1回で成功（取得1・確認済み適用1）。最後の重複抑制接続は動作テストで検証。これらは比較群への追加再測定ではない。機微情報検査修正により現在のエンジンハッシュは結果比較時と異なり、古い実行環境の結果キャッシュは失効する。現在版のキャッシュ動作は実コードの統合テストで確認済み。比較表を現行版の再測定値と称さない。

## ローカル導入と限界

`.local/memory-reuse/config.json`でobject/operation/changes/resultを有効、recent/procedureは無効にした。`.claude/settings.local.json`にプロジェクト限定のUserPromptSubmit/PostToolUse/PreCompact/Stopをマージし、既存の設定を保持。初回原本は無視対象の`.local/memory-reuse/settings.before.json`。installは重複を作らない。

対象のリンクは、検証済み原本の明示的なプロジェクト内ファイル参照、またはlinkコマンドを使う。操作のリンクは実際に照合された利用から学習する。記憶の作成・承認APIは従来どおり。既存ローカルMCPのreuseルートは明示的な有効化時だけ利用する。

汎用SDKの手順/結果の適用には信頼されたホストの操作アダプターが必要。今回実測したものは合成計画の検証アダプターであり、任意のBashを記憶から自動実行する機能ではない。通常の対象・操作・更新の提示は導入済み。通常ローカルDBの現時点のリンク数0、確認済みclaude知識×タスク0。自然利用の効果と複数機能併用効果は未観測、実際の他メンバーによるチーム効果も未観測。

各比較ではその案だけを有効化。同じ原本、同じツール、同じ成功条件、交互の条件順序を使用。8つの適用機会は同一の4原本を各2回使う設計。合成の種知識を使用し、自動抽出/承認・知識の自然増加は評価していない。小規模な単一課題型・時間やプロバイダーキャッシュの変動があるため一般化や統計的優越は主張しない。通常ユーザーのグローバルフックは比較で無効化し、両条件に同じ測定フックを使用。日常の全設定を含む絶対的な費用は未測定。

クラウド変更は保存済みsync-manifestと現行ローカルファイルを照合した。クラウド全体の変更が通常ツリーへ反映済みとは確認できず、隔離候補と通常ツリーは別である。今回、既存の追跡API/コレクターを保ったローカル実装として接続した。クラウドへの同期・展開は行っていない。照合はpreflight-local.json。
