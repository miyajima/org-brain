# Claude/Cursorの通常Stop経路の実動作確認

2026-10-19。指定対象のOrgBrainで、運用文書を読み取り検査する制御タスクを実クライアントに渡した。架空プロジェクトの履歴や、合成したStopをこの実動作の証拠には使っていない。原履歴・認証情報・候補本文はリポジトリに保存しない。

## Cursorで観測した結果

Cursor 3.25.6のThis Mac / org-brainで、Sonnet 5.5 / Lowの表示とタスク完了を画面確認した。利用者の入力操作補助を含むため、無人で画面操作まで完結した試験とは扱わない。モデル行のHigh表示を一時選択する操作は自動レビューで一度拒否され、利用者の明示承認後、送信前にLowへ変更した。Highのまま生成していない。

タスクは実際のSESSION_EXTRACTION.mdについて、失敗状態の優先・報告の未検証扱い・Stopと抽出ワーカーの分離の3項目を読む検査。実セッションでは3項目成功・終了コード0と報告された。これは文書の確認であり、3件の製品動作試験に成功したという意味ではない。

- 実行前の通常抽出キューは0件。実セッションのStop後にCursor由来の2ジョブがpendingになった。
- 2ジョブの11入力文すべてを、当該実セッションの正規の伏字処理後の入力と一致確認した。子エージェント履歴は読んでいない。
- 導入済みの通常CLIワーカーをCodexが見つからないPATHで実行。2ジョブ完了、1候補保存。応答が報告したモデルIDはanthropic/claude-sonnet-5.5、提供先Google。lowは要求とコード設定の値であり、サーバー内部の実装を独立に証明するものではない。
- 入力トークン880/766、出力11/82、判明費用は合計0.004222ドル。空の候補配列を返したジョブも完了に数え、空本文の記憶を作っていない。再送なし。
- 保存先は通常のmemory_learning_candidates。1件はdecision型のquarantine、capture_intent=review、推定判断、自動昇格禁止。
- 保存後の意味本文に、失敗を優先する理由、成功ツール証拠が必要という例外、3項目成功の報告とStop未検証という留保が残った。今回の結果報告はreported_verification専用項目ではなくrationale/constraints等の本文に含まれた。専用項目の保存成功とは言い換えない。
- observed_outcome / verified_outcomeはなく、報告を独立した実行証明や確定記憶に昇格させていない。

## 実Stop形式で見つかった修正

Cursorの通常ペイロードはcwdではなくworkspace_rootsを渡す。従来の回帰例はcwdを補っており、この対応漏れを隠していた。単一の有効な絶対パスを作業場所に使い、異なる複数ルートからは推測しないよう修正した。

対応漏れのテストは修正前に失敗し、修正後は最初の共通抽出16件、既存フック46件、導入バンドルでの対象2件が成功。独立レビューpass後、既存ランタイムをバックアップして更新し、バンドル一致を確認した。クライアントのMCP・認証設定は変更していない。

## Claude Codeで観測した結果

Claude CodeのOAuth失効・更新後の未ログイン状態は、cmuxでの実際のLogin successfulとEnterprise表示まで確認して解消した。制約付きの実行では既存ログへのリダイレクトが拒否され、履歴も保存できなかったため、そこを成功とせず証跡を分けた。Nodeだけを追加したCodexなしPATHと通常のOS環境で、新しい実セッションを作り、同じ文書検査を実行した。

その通常Stopは終了コード0だったが、初めはAPI要求の写しを会話と誤読して安全判定で除外した。Claude 2.1.302ではapi-request-blobにmessage.role=userが含まれる。実際のuser/assistant型の記録だけを採用するよう修正し、機密情報の判定を弱めずに解決した。思考ブロック、子エージェント履歴、API要求の写しは抽出へ渡さない。回帰テストは修正前に失敗し、修正後17件成功。実ユーザーの機密情報を含む入力が引き続き除外されることも確認した。独立レビューpass後、バックアップとバンドル一致確認を経て通常ランタイムへ導入した。

完了報告のターンは正常なルーターでoperational_historyになり、追加LLM抽出を呼ばなかった。そこで同じ実セッションで、実装済みの失敗優先規則・例外・先ほどの検査報告を今後の運用手順としてまとめる次の依頼を行った。通常ルーターを強制するオプションや合成Stopは使っていない。

- 実Claudeセッションの通常Stopが成功し、claude由来の4ジョブがpendingになった。
- 4ジョブの15入力文すべてが、同じ実セッションの最終ターンの正規処理後の入力と一致した。選択したのは実際の会話4レコードだけで、内部API要求を除外した。
- 通常CLIワーカーをCodexなしPATHで実行。4ジョブ完了・2候補保存・失敗0。API応答のモデルIDは4件ともanthropic/claude-sonnet-5.5、提供先Google。要求effortはlow。
- 2候補のそれぞれで、保存後の本文に数字だけで失敗を誤認するという理由、成功ツール証拠がない限り未検証という例外、文書3項目成功の報告が残った。
- 2件ともdecision型、quarantine、capture_intent=review、自動昇格禁止。reported_verification専用欄は生成されず、rationale/constraints等の本文に残った。observed_outcome / verified_outcomeはない。
- 抽出API4呼び出しの判明費用は0.008766ドル。再送はしていない。空候補配列の2ジョブも正常終了と区別して記録した。

Codex CLIをアンインストールした試験ではない。Claude実行と両方の抽出ワーカーでCodexを解決できないPATHを使い、Cursorでは実タスクがPython検査を実行して完了するところを画面確認した。GUIクライアントのOS全体からCodexを削除した証拠にはしない。

このMacに導入済みの通常設定を、同じworkspace mapping、対象allowlist、ローカルキュー、モデル設定で使うときの手順として再利用できる。Stopはキュー投入だけで、ワーカーは手動のmemory extraction runまたは既存メンテナンスで動く。今回は手動で通常ワーカーを呼んだ。自動スケジュールが発火した試験や、完全無人の画面操作試験ではない。

最終の関連回帰テストは共通抽出17件＋既存フック46件が成功。導入バンドルの対象3件も成功し、2つの形式修正はそれぞれ独立レビューpass。設定手順は[共通再抽出](../../docs/SESSION_EXTRACTION.md)、安全な集計は[native-client-verification.json](native-client-verification.json)。元履歴と候補本文は非公開のまま保持している。

最終の読み取りレビューは集計・照合証跡に対してpass。元履歴・UI・本文の意味確認は実行担当の観測であり、独立した意味採点ではない。レビューの要求モデル名を実ホストのモデル証明とは扱っていない。
