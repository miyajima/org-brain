# 自動保存の分類と重複統合

利用者の依頼により、今後のローカル自動保存へ提案・採用判断の区別と出典を残した
重複統合を実装した。既存記憶の一括再分類やCloudの保存規則は変更していない。

## 保存規則

- `classified-auto/v2` は、原文の役割と、選択・承諾が該当提案を指すことを確認する。
  質問、引用指示、複数案への曖昧な承諾、別件の承諾を採用根拠にしない。
- 提案、仕様説明、見込みは採用済みの判断と分けて保存する。根拠が確認できない
  提案は採用未確認のまま保存できる。種類の不明・不一致や本文不足は審査待ちとする。
- 承諾したユーザー原文と、対象提案の条件を保存する。分類メタデータをAIが
  指定しただけでは採用済みにならない。Stopの推論・モデル呼び出しは追加しない。
- 本文、理由、再利用条件、適用先、分類、採用状態、テナント、プロジェクト、
  作業区分、業務分類、公開範囲、出典の区分、検証状態が一致する重複だけを統合する。
  コードの空白や条件・例外を取り除いて同一視せず、意味が似ているだけでは統合しない。
- 統合時は同じ記憶IDを使い、出典・証拠・発生イベントを追加し、検索用データを更新する。
  検証状態の引き上げや有効期限の延長は行わない。出典・証拠の保持上限を超える場合は
  別記憶に保存して原本参照を失わない。

設定と再利用条件は [自動保存の手順](../../docs/MEMORY_CLASSIFIED_AUTOSAVE.md) を参照。
通常の今後の保存で適用される。元の審査方式へ戻す場合は
`ORGBRAIN_MEMORY_AUTO_SAVE_CLASSIFIED=false` とする。

## 検証と反映

- 失敗を確認してから実装した分類・重複テスト15件が通過した。
- 保存・検索・確認・契約・source intakeを含むNodeテスト72件が通過した。
- 共通抽出、自動起動、3経路のNodeテスト37件が通過した。
- hookとセッション再生のVitest 53件が通過した。
  15件は72件に含まれ、関連テストは計162件。
- 配布用CLIの実Stopを隔離DB・モックAPIで通した後、稼働CLIを置き換えた。
  稼働パスでも同じ実Stopの確認1件が通過した。原文に基づく明示的な判断、
  条件保持、未検証状態、待機候補なしを確認した。
- 旧CLIのバックアップを保持した。設定・認証情報・既存記憶DBは変更していない。
  接続中のMCPプロセスを強制再起動しておらず、MCP側の新コードは新しいプロセスから有効。
- 実モデルによる分類精度、自然な会話の次回Stop、費用・速度・利用効果は未測定。
  ローカルの挙動テストをそれらの測定結果には置き換えない。

この規則は原文と分類を保った今後の自動保存で使う。曖昧な自然言語の意味を
全面的に判定するものではなく、明示的な根拠がない内容は採用済みと認定しない。
