# 通常Claude作業への導入と実資料評価

2026-10-30。追加最大18 CLI開始、累計437、API換算3.60 USD以内。準備・失敗・再測定も含む。クラウド展開はしない。実請求額と親の実装・監査費は別勘定で不明。

## 対象

プロジェクトの現行実装の調査、保存済み測定原資料の再集計、通常利用手順書を作る。合成資料や固定モデル応答は使わない。原資料の具体的な選択は `project-config.json`、原本のハッシュは `manifest.json` と変更前の `manifest-history/`、課題は `cases.json` に固定する。元の合成資料実験の測定値を再分析する課題であり、新しい実利用効果へ読み替えない。

各種類の最初の2単位を実モデルで作成する初回3件と、同じ範囲の再依頼・新しい第3単位を追加する依頼の2件を用意する。記憶なし6件に対し、再利用6件は利用者が既存成果・差分・全体を自由に選ぶ。既存成果で完了なら追加モデル開始は0。利用者の選択を自動生成しない。

## 比較と検証

両条件で同じ原資料・対象・固定アダプター・品質条件を使う。記憶なしでもホストが資料を準備する効率化を適用する。Claudeの通常システムとプロジェクト設定を使用し、モデルは `claude-sonnet-5-5`、effortはmedium、作業ツールは同じBashとする。既存成果の提示は記憶なしでは行わない。CLIの実版・実モデルはイベントから確認する。並行テスト・ビルド・Wiki作業中に時間測定しない。

ネイティブ呼出ID、実引数、アダプターの実出力、完成ファイルのハッシュ、元の成果と承認範囲を照合する。残すべき節の完全一致、数値の分母・単位、条件と未観測事項の保持、元資料にない断定がないことを確認する。提示だけや本人の利用報告だけで適用を認定しない。ファイル原本から作る成果を新しい記憶件数には数えない。

## 人の時間

ターミナルでは表示から実回答までの経過時間を測る。今回のネイティブUIで複数課題を一度に確認する場合は、質問送信から実回答受信までの観測窓を1回だけ計上する。課題数で複製・恣意的な按分をしない。UIの待ち時間や親処理も含まれ得るため、能動的な確認時間とは区別する。本人の申告がなければ能動的な時間は欠測。

機械処理時間、着手前確認を含む時間、最終的な人の成果確認・修正を含む総時間を分ける。最終確認が未観測なら全作業の人を含む時間削減は未検証とする。評価で依頼した利用は `solicited`、自発的な通常利用は `organic` とし、実チーム利用とは分ける。

## 開始時に確認した問題

初回は認証を参照できずCLIがモデル前に停止。1回として計上する。認証参照可能な実行環境で再開する。次の実モデル試行では長いフック文脈が省略され、モデルが作業を完了しなかった。失敗・費用を残し、資料本文を起動時の追加文脈へ移して完全なバイト列とダイジェストを照合する。フックの10,000文字超過時の退避は[公式仕様](https://code.claude.com/docs/en/hooks#add-context-for-claude)で確認した。失敗を比較結果へ混ぜず、準備・修正費として別記する。
