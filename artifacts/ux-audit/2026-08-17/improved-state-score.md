## 画面・フロー別評価

1. 組織の活動 — **89 / 100**。最初の表示領域が「要対応シグナル → 健全性サマリー → 分析用トポロジー」の順になり、重大項目からTaskへ直接進める。正常時も最終観測時刻と正常状態を表示する。
2. 管理ナビゲーション — **93 / 100**。単一定義からデスクトップとモバイルを生成し、知識管理・ユーザー／組織・システム運用の3群へ整理した。両表示の到達ルートはテスト上完全一致する。
3. 知識のつながり — **86 / 100**。3Dマップを標準表示のまま維持し、検索可能なノード一覧をマップ前に常時表示する。種類・名前・プロジェクト・確認状態を読み取れ、選択中ノードは先頭へ同期する。
4. 判断詳細 — **86 / 100**。判断トレースが成功している場合、補助メタデータ取得失敗を主エラーにせず、APIパスなどの技術エラーも露出しない。
5. 知識の履歴 — **79 / 100**。既存の行動優先構成を維持し、共通ナビゲーション・言語・スコープ保持の改善を受ける。
6. Task監視 — **92 / 100**。正常・不存在・Task APIエラー・イベントのみエラーを区別し、すべてに一覧へ戻る／再試行／運用画面の次操作を提示する。失敗・隔離Taskは既存APIで再実行できる。
7. 運用ステータス — **89 / 100**。既存の強い「重要度・説明・件数・行動」パターンを保ち、3言語化、文字サイズ、操作対象、通知の一貫性を改善した。
8. ユーザー管理 — **91 / 100**。招待と既存ユーザーを明確に分け、ロールと状態を利用者向けの3言語ラベルで表示する。成功・エラー・空状態も共通パターンになった。
9. モバイル — **88 / 100**。主要管理機能への到達差を解消し、390 x 844の最初の画面内でデータ鮮度と要対応項目を確認できる。ノード検索も3D領域より前に表示する。

## 自動検証による根拠

- 主要7ルートの `@axe-core/playwright` 検査で、impactが `critical` または `serious` の違反は **0件**。
- デスクトップ／モバイルの管理リンク一覧が一致することをDOM比較で検証。
- `lang=en | ja | zh` の各遷移後に `tenant_id`、`project_id`、`lang` が維持されることを検証。
- Task詳細の4取得状態と失敗Taskの再実行導線をE2Eで検証。
- 390 x 844で鮮度表示と要対応カードが初期ビューポート内にあることを座標で検証。
- 3Dノード・キーボード一覧・URL・判断トレースの選択同期をE2Eで検証。
- 横スクロールがないことを既存および追加のレスポンシブテストで検証。

## 残る改善余地

- 監査画像を取得したChromium環境ではWebGLが利用できず、3D領域は一覧フォールバックになった。3D描画そのものは既存実装を維持し、利用不能時も一覧と判断トレースで操作を完了できることを確認した。
- 一部の密度が高い分析ビューでは、補助情報が12px付近に残る。重大なコントラスト／構造違反はないが、200%ズームと実スクリーンリーダーの手動検証は次の品質確認候補となる。
- 全管理画面の主要コピーは3言語化したが、APIが返す自由記述や固有名詞は翻訳対象外である。
