## 減らした往復と維持した確認

- 現行はモデルが質問→差分を読取→全体を書込む。10件でモデル応答40回。改善版はモデル起動前にローカルで明示選択を受け、ホストが承認された新しい単位だけを読み、モデルは新しい単位のpatchだけを書く。モデル応答20回。記憶なしは全体の読取・生成で30回。
- バックエンドの読取は各条件10回のまま。改善版でモデルの読取ツールが0回になった分は、ホストが10回実際に実行している。読取そのものが消えたと扱わない。新しく調査・生成した対象は30→10単位で、20単位を既存成果から保持した。物理的なファイル読取バイト数の削減率ではない。
- ローカルの回答は、今回の依頼文・対象単位・利用者・セッション・原本の状態・既存成果IDを結び付けた一回限りの記録とした。未回答では作業を開始しない。モデルが回答を作ったり、別利用者・別タスクへ流用したりする経路にはしていない。
- ホストが実際に読んだ資料とUserPromptSubmitが実際に渡した文脈のダイジェスト、モデルの実際のBash引数、PostToolUse、成果物を別実装の監査で照合した。ホストの処理を架空のモデルの読取IDへ変換しない。
- モデルは既存部分を再生成せず、新しい部分だけを返す。ホストが既存部分を一字も変えずに結合し、最終成果全体の必須事項を確認した。

主比較30回はruntime/v2で完了した。レビューで、回答が済んでいても資料の注入前はモデル側の全操作を止めることと、30分を超えたローカル確認ではホスト読取も開始しないことを補強した。失敗テスト2件を作ってから修正し、確認テスト26件・既存回帰44件、計70件を通過した。変更は2つの停止条件で、原本・課題・アダプター・最終成果条件は変更していない。

登録した対象での差分再利用として暫定採用できる結果を得た。プロジェクトの通常設定は保持しており、実業務用の対象登録・自然利用は未観測。機能の利用にはdocs/MEMORY_REUSE_TASK_CONFIRMATION.mdのtask_local_mode、local_source_fieldと起動コマンドを使う。直接Claudeを起動する従来経路は維持した。クラウド展開、push、外部への通知は行っていない。
