## 改善する処理

- ローカルの起動コマンドが、実行前に既存成果の作成者・日付・範囲・不足・所在を示す。ターミナルで既存成果で完了／差分だけ実施／全体を実施を選ぶ。未回答は承認せず停止する。
- セッション・利用者・原本・既存成果・今回の範囲・依頼文を結び付けた一回限りの選択記録を使う。モデルに選択させない。
- ホストが承認された差分だけを実アダプターで読み、その実結果をUserPromptSubmitで渡す。資料の読取と注入はhost_contextとして記録し、モデルが読取ツールを呼んだという記録へ変えない。
- モデルは新しい部分だけをpatchとして生成する。ホストが変更を許可していない既存部分をそのまま結合し、全体の成果物を作る。実際のモデルのBash呼出とPostToolUse、生成物を照合する。
- 選択、原本、権限、期限、成果物が途中で変われば、再利用成功へ変換しない。

## 合格条件と観測

記憶なしと同じ全3単位の最終成果、必須の事実・数値、誤適用0、既存部分の保持、範囲外操作0、回答証拠と実操作の照合を確認する。個人・模擬共有それぞれを分ける。原本のモデル利用、既存成果の再利用、ホスト読取・注入、モデルによる差分生成を別記する。利用報告だけで成功と認定しない。

4区分の総トークン、全モデル応答数、調査対象・操作・修正の回数、API換算、モデル起動前の検索・確認・資料準備・注入・追跡とCLIを合わせた機械時間を測る。全件を対照・現行・改善版で同じ台帳へ残す。個別のCPU金額、実請求、親実装・監査費は未取得として区別する。

利用者は明示的なテスト専用入力で模擬する。置き換えるのは利用者の選択だけであり、モデル応答は再生しない。人の待ち時間は未観測。前回の短い合成資料を変更せず使うため、一般の長い調査や実チームの効果は主張しない。

改善版が成功条件・確認精度を保ち、記憶なしより総トークンと機械時間をともに減らすかを判定する。未達は未達として報告し、有利な課題への変更や未承認の追加実行をしない。通常設定は保持し、クラウド展開はしない。
