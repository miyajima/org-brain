# 成功・失敗のセッション抽出改善（2026-10-27）

## 結果と範囲

ローカルの抽出・証拠収集・共有検証を修正した。クラウド配備、公開、インストール済みruntimeの更新、実モデルによる再抽出、実記憶の採用は行っていない。既存の未コミット変更と隔離したworktreeで実装・テストし、変更対象だけを元のorg-brainへ反映した。

検索原本は `search-protocol.json` にバイト一致で保持した。指定された4原本のSHA-256は `input-manifest.json` に記録した。成功候補10件は審査用の探索標本であり、正解集合ではない。会話全文や原文投影は成果物に保存しなかった。固定した比較対象コード4ファイルの前後ハッシュ、会話・ターン・最終回答行とハッシュは `offline-comparison.json` にある。

## 原因と変更

1. 既存routerが操作状況だけと判断した成功・復旧・再利用の記録が、モデルへ送る前に落ちていた。共通セッション抽出の入口で、成功側と失敗側の両方を探索する補助条件を加えた。操作に加え理由または条件を必要とし、検索一致だけでは採用しない。
2. 単一ターンの読み取りでは以前の失敗を失う。Codexアダプターは、連続する直前3ターンまで、同じworkspace・ツール名・引数ハッシュで少なくとも一方が失敗した操作を接続する。合計8 MiBまで。対象のsession/workspaceを照合し、期間検索には作成日でなくターン日時を使う。期間内の最新ターンが進行中でも直近の完了ターンを検索できる。
3. 関連する原因・修正・再検証が別断片に分かれ、予算境界で別々に提示され得た。同じ操作の証拠と間の文脈をまとめ、過大なら全体を保留する。ターン・日時・操作ID・元証拠ハッシュを保持する。全文保持モードで24件を超えた結果の対応イベントも保持する。
4. 明示された失敗状態を優先しつつ、exit code 0の出力内の「0 failed」を失敗と誤判定しない。分析・引用会話・子/他チャット報告は実行証拠から除く。既知の資料readは `record_read` として当時の実行成功と区別する。
5. 新packetの `episode_profile=session-episodes/v1` は共有検証器で本人判断・理由・条件・ツール結果の対応を検査する。不足する成功の4項目は明示的なgapsとして残す。厳密に同じ復旧の成功・失敗だけを1候補にまとめ、両タグを保持する。回帰・未解決・報告のみと、明示されたテスト先行開発の文脈を分ける。

TLS・Studio接続と後続の配信・Play、保存報告と当時の実行、合成課題と自然利用は別扱い。本人判断をassistant報告から推測しない。秘密情報拒否、quarantine、automatic_promotion=false、確認手順を維持する。

## 再利用手順と限界

`node --test scripts/session-extraction-episodes.test.mjs` で同じ境界を再検証できる。原本10件の比較は `scripts/evaluate-session-episodes.mjs --candidates <指定JSON> --baseline <未変更checkout> --output <結果JSON>` をNodeで実行する。baselineは `offline-comparison.json` のコミットとファイルハッシュで照合する。モデルや実キューは呼ばない。

効いた理由は、探索の広さと採用の厳しさを分け、関連証拠を同じまとまりで検証し、別ターンや入力上限で消えた条件を可視化できたため。抽出入口、操作対応、出典帰属、入力保留の変更時に再利用する。

制限: ターン間接続は現状Codexの連続3履歴だけで、引数変更・遠い履歴は結ばない。任意シェル/JavaScript wrapperの意味や自然言語の因果を完全には判定しない。期間フィルタは記録されたターン日時を用い、日時不明を推測しない。実モデルの発見・誤抽出・採用効果と、親モデル・修正・検証を含む総費用は未検証。今回の追加抽出provider呼び出しは0だが、作業全体の費用0や節約は主張しない。
