## 採否と再利用条件

3機能をこのプロジェクトのローカル通常設定で有効化した。設定は `.local/memory-reuse/config.json` の `task_request_mode=sections_stdin`、`task_compact_receipts=on`、`task_full_checks=current_sources_only`。既存の他の設定値を保持し、変更前のバックアップを保存した。通常DBへ評価用成果を取り込んでいない。導入後に一覧と `document --prepare-only --control --origin solicited` を実行し、モデル開始0で通常経路の準備が通った。起動は従来の `pnpm claude:work research|analysis|document`。詳しい手順・復旧は [通常作業の手順](../../docs/MEMORY_REUSE_ORDINARY_WORK.md)。

引用符を含む調査・分析・文書作成の本文を、安全に実操作へ渡す場合に使う。3択の人の確認は維持する。全体実施では旧成果の適用を記録しない。今後の省力化を狙う場面は、判断で全作業を省ける既存完了、または十分大きい調査を省ける差分である。短い全体実施のためだけに人へ確認を追加して時間削減を期待しない。

自然発生した通常再利用、実チームの採用、人の最終確認・修正時間、実請求額は今回未観測。今回の新規評価は全件localの依頼済み課題で、チーム利用の再実測ではない。前のチーム模擬結果を今回の実チーム効果へ置き換えない。モデル評価はここで終了し、残りの承認枠1回は使わない。
