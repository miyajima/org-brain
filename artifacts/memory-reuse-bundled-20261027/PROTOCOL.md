# 報告同梱と最新確認の段階比較（提案）

既存の270回に追加60回・累計330回という上限変更の回答を受領した。費用見積もりと停止基準はbudget-proposal.jsonを参照。まず改善1の実装とローカル境界テスト、改善1の比較、次に改善2の実装と境界テスト・比較を行う。クラウド展開なし。

- 段階1: 記憶なし・現行inline・操作への明示申告同梱を各10回。
- 段階2: 記憶なし・改善1・軽い最新確認で重複調査を省く版を各10回。
- 各条件は個人5・模擬チーム5、4知識に8適用機会、対象外2。段階2は別の固定入力。
- 同じ合成原本・ツール・成功条件を使い、条件順を課題ごとに循環。モデル/effortはclaude-sonnet-5-5/medium固定し実ログで確認する。
- 検索・注入・モデルが選んだ参照・ネイティブ操作・完了・確認済み利用・課題成果を別に記録する。申告同梱を独立した架空のreport呼び出しへ変換しない。
- 成功/必須条件保持の悪化なし、3知識以上、個人/チーム各2課題以上、対象外誤適用0。欠測と誤認定を別記し、既存方式と照合する。
- 入力・キャッシュ作成・キャッシュ読込・出力を合計。原本の作成/更新、事前検証、検索、注入、追跡、修正の費用を含め、内訳が取れない処理は未分離とする。
- 最新確認は入力・出典バイト/版・環境・期限・権限が一致した場合だけ。適用する計画はモデルが生成し、固定回答や結果の再生を実モデル評価として数えない。
- CLIの準備・失敗も60回に含め、追加の再比較や自動再送はしない。API換算約1.50 USDの見積もりは直近単価から計算し、削減効果を前提にしていない。
- API換算の停止基準案2.00 USD、CLI単位の予算設定案0.10 USD。実請求と親Codexの実装費は未取得で別扱い。
